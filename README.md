# FluidCalc — микротермометрия флюидных включений

**Исследовательский прототип.** Не является аттестованным программным обеспечением для публикационных
оценок давления или состава флюидов. Успешные автоматические тесты — это не независимая научная валидация.

Программа ведёт журнал микротермометрических наблюдений и выполняет **только** проверенные расчёты ядра
`fluid_core` (без изменения коэффициентов):

| Наблюдение | Расчёт | Источник |
|---|---|---|
| Tm лёд | солёность, мас. % NaCl-экв. | Bodnar (1993), DOI 10.1016/0016-7037(93)90378-A |
| Tm клатрат | солёность водной части, мас. % NaCl-экв. | Darling (1991), DOI 10.1016/0016-7037(91)90079-K |
| Th CO₂ + направление гомогенизации | плотность насыщенной жидкой **или** газовой чистой CO₂, P_sat CO₂, мольный объём | Span & Wagner (1996), DOI 10.1063/1.555991, через CoolProp |
| Tm CO₂, Th общ., Te | только регистрация, расчёт не выполняется | — |

P_sat — давление насыщения чистой CO₂ при Th CO₂, **не** давление минералообразования.

## Целевая система

OSNova Linux Onyx 2.7 (x86_64, glibc 2.28, KDE), Miniforge в `~/miniforge3`, окружение `fluidcalc`
(Python 3.11, CoolProp, PySide6, matplotlib, openpyxl). Системный Python, glibc и настройки OSNova
не используются и не изменяются. Сборка EXE не нужна.

## Установка (один раз)

Окружение `fluidcalc` у вас уже создано. Скопируйте каталог программы, например в `~/FluidCalc`, затем:

```bash
cd ~/FluidCalc
```

```bash
./install_desktop.sh
```

Скрипт создаёт ярлык в меню приложений (`~/.local/share/applications/fluidcalc.desktop`) и на рабочем
столе. Права администратора не нужны. Если KDE спросит о доверии к ярлыку — подтвердите.
Удалить ярлыки: `./uninstall_desktop.sh`.

Проверка окружения (версии, glibc, CoolProp):

```bash
~/miniforge3/envs/fluidcalc/bin/python tools/check_env.py
```

Если окружения нет (новый компьютер; интернет нужен только на этом шаге):

```bash
~/miniforge3/bin/conda env create -f environment.yml
```

Рекомендуется зафиксировать точный состав окружения (lock-файл) на вашей машине:

```bash
~/miniforge3/bin/conda list -n fluidcalc --explicit > conda-lock-osnova.txt
```

## Запуск

* двойной щелчок по ярлыку **FluidCalc** на рабочем столе или в меню «Наука»;
* или `./fluidcalc.sh` (в Dolphin: двойной щелчок → «Выполнить»);
* другая база: `./fluidcalc.sh /путь/к/базе.sqlite`.

Если Miniforge установлен не в `~/miniforge3`: `FLUIDCALC_CONDA=/путь/к/miniforge3 ./fluidcalc.sh`.
Ошибки запуска показываются окном (kdialog) и пишутся в `~/.local/share/fluidcalc/logs/launcher.log`.

**Работа без интернета.** После установки зависимостей сеть не требуется: все расчёты (включая CoolProp),
база SQLite, графики и справка — локальные. Это проверяет тест `tests/test_plots_offline.py`
(полный цикл импорт → расчёт → графики при заблокированных сетевых соединениях).

## Работа с программой

* **Дерево слева:** проект → образец → минерал → FIA → включение (правая кнопка мыши — добавить,
  переименовать, удалить). Неуказанный минерал/FIA показывается как «(минерал не указан)» — значения
  не придумываются.
* **Три вида сведений.** Программа различает НАБЛЮДЕНИЕ (измерено и записано), РАСЧЁТ (число по опубликованному
  уравнению, статус «рассчитано») и ИНТЕРПРЕТАЦИЮ (диагностическое заключение без числа, статус «интерпретация
  (не расчёт)»). Если данных для расчёта не хватает, строка получает статус «отказ» с объяснением; отсутствующие
  измерения не подставляются, выбирать коэффициенты или методики не требуется.
* **Измерения:** журнал наблюдений (Tm лёд, Tm клатрат, Tm CO₂, Th CO₂, Th общ., Te, Tm гидрогалит, T раств. галита) с погрешностью,
  направлением гомогенизации, фазовыми признаками («не указано / да / нет»), описанием фаз.
  «Добавить…» (Ctrl+N) — ввод отдельного измерения.
* **Импорт CSV / Excel** (Ctrl+I): CSV (UTF-8 или Windows-1251; разделитель `,` `;` или табуляция;
  десятичная точка или запятая, знак «−») и XLSX (выбор листа). Карта полей с автоподбором,
  просмотр исходных данных, построчная проверка; строки с ошибками не импортируются; точные дубликаты
  пропускаются. Исходный файл не изменяется (в журнал импорта пишется его SHA-256).
  Форматы: длинный (`examples/example_input.csv`) и широкий (`examples/example_wide.xlsx`,
  `examples/example_wide_ru.csv` — **синтетические** данные для проверки интерфейса).
* **Лабораторная сводная таблица** («Таблица 1/2/3»: блоки по образцам, двухстрочная шапка «Тгом. | тип |
  Т тр. газа | Тэвт | Тпл. г-гил. | Тпл. льда | С% | … | d фл | Рфл | форма | местонах»): «Файл → Импорт
  лабораторной таблицы» переносит измерения в журнал (результаты лаборатории С%, d фл, Р фл сохраняются в
  комментариях, а не как измерения; «группа N» — группировка исследователя, не FIA). «Файл → Сверка
  лабораторной таблицы» пересчитывает солёность и проверяет физическую допустимость плотностей; то же из
  командной строки: `python tools/compare_lab_table.py ТАБЛИЦА.xlsx СВЕРКА.xlsx`. Разбор методики —
  `docs/LAB_METHOD_REVIEW.md`.
* **Доля углекислотной фазы φ** (правая кнопка на включении → «Доля углекислотной фазы…» или столбец «φ» при
  импорте): по ней для включений с CO₂ рассчитывается **плотность включения** по объёмному балансу фаз
  (результат «ρ включения» с паспортом и диапазоном при φ ± погрешность).
* **Включения H₂O–CO₂–NaCl, строгая модель** (Steele-MacInnis, 2018; результат «Состав, ρ H₂O–CO₂–NaCl»).
  Что нужно ввести:
  * режим 1 (клатрат плавится раньше гомогенизации CO₂): Tm клатрата с отметками «жидкая CO₂ — да, газовая CO₂ —
    да, раствор — да»; Th CO₂ с направлением гомогенизации и флажком чистой CO₂;
  * режим 2 (CO₂ гомогенизируется раньше плавления клатрата): то же, но при плавлении клатрата отмечена только
    одна углекислотная фаза — та, в которую прошла гомогенизация;
  * режим 3 (жидкой CO₂ нет): Tm льда и Tm клатрата с отметками «жидкая CO₂ — нет, газовая CO₂ — да, раствор — да»
    и флажком чистой CO₂ у Tm клатрата;
  * во всех режимах — доля углекислотных фаз φ и температура её оценки (не ниже Tm клатрата). Если φ не измерена,
    используется Th общ. с гомогенизацией в жидкость (выше 200 °C результат помечается как ориентировочный).

  Программа сама ничего не подставляет: если данных не хватает или записанные фазы противоречат режиму, в строке
  результата написано, чего именно не хватает. Выводятся плотность, валовый состав, солёность, молярный объём,
  давления внутри включения при фазовых переходах и изохора (300–600 °C). Если есть Th общ. в жидкость, отдельно
  показываются **давление на линии расслоения** и **давление по изохоре** при Th общ. и их расхождение — это два
  разных расчёта, они не взаимозаменяемы и **не являются давлением захвата**. Выдаётся сошедшееся решение; при
  несходимости или физически недопустимом решении расчёт отклоняется с объяснением. Числа немного отличаются от
  программы автора в Excel (солёность до 0,3 % относительных, плотность до 0,05 %) — см. раздел 16 отчёта валидации.
* **Te — диагностическая интерпретация**: перечень кандидатов солевой системы (около −21,2 °C — NaCl, с оговоркой о
  NaCl–KCl; −33…−38 °C — MgCl₂ и FeCl₂ одновременно; −50…−52 °C — CaCl₂; ниже −55 °C соль не назначается).
  Состав по Te не определяется: первое плавление может быть метастабильным.
* **Tm CO₂ — диагностическая интерпретация**: сравнение с тройной точкой чистой CO₂ (−56,558 °C) с учётом
  погрешности. Мольные доли CH₄ и N₂ не выдаются; данные КР-спектроскопии можно отметить у наблюдения.
* **T раств. галита → солёность** (Sterner et al., 1988): только если отмечено, что при растворении галита
  присутствует пар.
* **Tm гидрогалит → солёность** (Steele-MacInnis et al., 2011, бинарная система H₂O–NaCl): только если отмечено, что
  фаза определена как гидрогалит, и нет признаков CaCl₂/MgCl₂/FeCl₂ (по Te или отметке у включения).
* **Условия захвата при независимом ограничении** (правая кнопка на включении → «Состав солей и независимое
  ограничение…»): по заданной оператором температуре ИЛИ давлению (либо диапазону) программа находит точку на
  рассчитанной изохоре. Результат называется «условия захвата включения при независимом ограничении» и не
  выдаётся за условия минералообразования, пока оператор не отметил, что одновременность захвата и роста минерала
  документирована. Подробности и ограничения — `docs/INTERPRETATION_AND_SALINITY.md`.
* **Водно-солевые включения (H₂O–NaCl)**: при наличии Tm льда и Th общ. с гомогенизацией **в жидкость** программа
  рассчитывает плотность включения, давление при Th (минимальное давление захвата), наклон и точки изохоры
  (корреляции HokieFlincs; результат «ρ, Ph H₂O–NaCl»). Давление захвата не выдаётся без независимой оценки T.
* **Экспорт в формате лабораторной сводной таблицы**: «Экспорт результатов…» → «Сводная таблица в формате
  лаборатории» (давление захвата намеренно не выводится — см. `docs/LAB_METHOD_REVIEW.md`; для включений с CO₂
  добавлены столбцы строгой модели и её предупреждения).
* **Расчёт** (F5 — выбранный узел дерева, Shift+F5 — вся база) выполняется в фоновом потоке. Каждый расчёт
  сохраняется отдельной версией со снимком входных данных и версиями программ; прежние не перезаписываются.
* **Результаты:** таблица со статусами «рассчитано / отказ / не рассчитывается» и **паспорт результата**:
  входные данные, методика, уравнение, область применимости, источник и DOI, допущения, ограничения,
  предупреждения, версии. При погрешности u показываются значения при T ± u (оценка чувствительности,
  не полный бюджет неопределённости).
* **Экспорт:** XLSX (листы «Результаты», «Паспорта», «Расчёт», «Методики и источники», «Ограничения»),
  CSV для русской локали (`;`, десятичная запятая) или международный CSV; экспорт таблицы измерений
  (повторно импортируется); резервная копия базы и выгрузка всей базы в XLSX (меню «Файл»).
* **Графики:** Th общ. — солёность, распределения Th общ., солёности, Th CO₂ по образцам/FIA;
  сохранение PNG/SVG. Без интерпретаций (полей, трендов, изохор).
* **Быстрый расчёт:** одно значение без записи в базу.
* **Методики и ограничения:** справка по методам, источникам, нереализованным моделям и незавершённой проверке.

Расчёт блокируется (статус «отказ» с причиной), если: температура вне области применимости; для Darling не
подтверждено (или не указано) сосуществование жидкой CO₂, газовой CO₂ и водного раствора; для CO₂ не указано
направление гомогенизации (ветвь не выбирается автоматически), гомогенизация критическая, не принято
приближение чистой CO₂ или Th CO₂ ближе 0,10 °C к критической точке.

## Данные и журналы

## Тесты

```bash
./run_tests.sh
```

Запускаются программные тесты (`tests/`) и научная валидация (`validation/`) — без дисплея
(`QT_QPA_PLATFORM=offscreen`), во временном каталоге данных, рабочая база не затрагивается. Полный журнал с версиями
пишется в `docs/TEST_REPORT.txt`, в конце — раздельная сводка passed/failed/skipped по обоим наборам.
Командная строка ядра (без GUI) по-прежнему доступна:

```bash
~/miniforge3/envs/fluidcalc/bin/python -m fluid_core examples/example_input.csv /tmp/results.csv
```

## Научная валидация

Отдельно от программных тестов в каталоге `validation/` проверяются:

* контрольные точки с источниками, DOI/URL, классом свидетельства и обоснованным допуском (`checkpoints.csv`);
* калибровочные экспериментальные данные Hall et al. (1988) для Bodnar и Chen (1972) для Darling
  (`data/*.csv`) — по двум раздельным критериям: регрессионному и экспериментальной совместимости;
* неизменённая выгрузка NIST WebBook для насыщения CO₂ (−50…+30 °C).

```bash
~/miniforge3/envs/fluidcalc/bin/python -m validation
```

Результат — `validation/VALIDATION_REPORT.md` и `validation/results/*.csv`. Выявленные расхождения
(1 у Hall, 17 у Chen по экспериментальному конверту) зарегистрированы в `validation/known_discrepancies.csv`
и показываются как FAIL / «несовместимо», а не скрываются. Новое или исчезнувшее расхождение даёт ненулевой
код возврата. Исходные материалы аудитов хранятся без изменений в `validation/sources/`
(см. `PROVENANCE.md`); копии ядра в них только для воспроизведения аудита.

Калибровочные данные независимы от кода, но использовались при построении уравнений, поэтому независимая
валидация моделей **не завершена**: статус — `docs/VALIDATION_STATUS.md`, открытые вопросы —
`docs/OPEN_VALIDATION_QUESTIONS.md`. `./run_tests.sh` запускает оба набора и возвращает ненулевой код при сбое.

## Чего программа не делает

Не определяет состав солей (NaCl/CaCl₂/MgCl₂/FeCl₂) по Te (выдаётся только диагностическая интерпретация); не
оценивает мольные доли CH₄ и N₂ по Tm CO₂; не выдаёт давление или температуру минералообразования;
не считает Th температурой образования; сама по себе изохора не даёт давления захвата — условия захвата
выдаются только при заданном оператором независимом ограничении по температуре или давлению; не смешивает
визуальную долю пузырька при комнатной температуре с плотностями фаз при Th; не управляет оборудованием Linkam.
Список нереализованных моделей — в `docs/VALIDATION_STATUS.md`.
