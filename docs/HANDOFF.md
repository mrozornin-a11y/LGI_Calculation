Состояние на 2026-11-13. Единственная рабочая ветка — ветка по умолчанию `maim`; все

Незавершённой работы в репозитории нет: всё перечисленное в разделе «Что реализовано» проверено тестами,
всё остальное перечислено в разделе «Что осталось».

## Что реализовано

| Этап | Что считается | Где |
|---|---|---|
| 0–1 | Солёность по Tm льда (Bodnar, 1993) и Tm клатрата (Darling, 1991); плотность чистой CO₂ (Span & Wagner через CoolProp); плотность включения по объёмному балансу | `fluid_core/salinity.py`, `co2.py`, `brine.py` |
| 2а | H₂O–NaCl (HokieFlincs): плотность, давление при Th, линейная изохора | `fluid_core/h2o_nacl.py` |
| 2б | H₂O–CO₂–NaCl (Steele-MacInnis, 2018), режимы 1–3: состав, плотность, давления при фазовых переходах, изохора; расчёт по Th общ.; давление на линии расслоения | `fluid_core/h2o_co2_nacl.py`, `co2_duan1992.py`, `clathrate.py`, `co2_brine.py`, `duan1995.py`, `mao2013.py` |
| 2в | Диагностические интерпретации Te и Tm CO₂; солёность по растворению галита (Sterner et al., 1988) и плавлению гидрогалита (Steele-MacInnis et al., 2011, бинарный предел); условия захвата при независимом ограничении | `fluid_core/interpretation.py`, `halite.py`, `trapping.py` |
| Интерфейс | PySide6, база SQLite (схема v3), импорт CSV/XLSX и лабораторных сводных таблиц, экспорт XLSX/CSV и лабораторной таблицы, графики, паспорта результатов | `fluid_app/` |

Принципы, действующие во всём проекте:
* программа различает НАБЛЮДЕНИЕ, РАСЧЁТ и ИНТЕРПРЕТАЦИЮ; при нехватке данных выдаётся отказ с объяснением;
* ничего не подставляется: направление гомогенизации, фазы при переходах, чистота CO₂, температура оценки φ,
  независимое ограничение — только явно;
* формулы, коэффициенты и границы `fluid_core/salinity.py` и `fluid_core/co2.py` не менять;
* для H₂O–CO₂–NaCl выдаётся сошедшееся решение с проверкой невязок и физической допустимости; схема программы
  автора (`numerics='author'`) — только для сравнительных тестов, без переключателя для пользователя;
* ни одно выводимое давление не называется давлением захвата или минералообразования; условия захвата выдаются
  только при заданном оператором независимом ограничении;
* авторские эталоны (`validation/data/*_oracle.csv`) не изменять; макросы авторских программ не запускать;
* реальные данные лаборатории и тексты статей в репозиторий не добавлять.

## Что осталось

* Режим 4 модели H₂O–CO₂–NaCl (давление CO₂ по КР-спектроскопии) — отложен.
* Бинарная VX-модель CO₂–CH₄ / CO₂–N₂ (Thiéry et al., 1994); смесь CO₂–CH₄–N₂ — не реализованы, сейчас только
  диагностика.
* Растворение галита после исчезновения пара; полная инверсия H₂O–NaCl–CaCl₂; гомогенизация включений с галитом
  в HokieFlincs — не реализованы.
* Гомогенизация H₂O–CO₂–NaCl в углекислотную фазу и критическая; гомогенизация H₂O–NaCl в газ — не реализованы.
* Импорт отметки о данных КР-спектроскопии из таблиц (сейчас вводится только в диалоге наблюдения).
* Этап 3 «удобство» из `docs/ROADMAP.md`: сводки по образцу/FIA, шаблон журнала измерений.
* Проверка на целевой машине OSNova (см. «Известные проблемы»).

Открытые научные вопросы — `docs/OPEN_VALIDATION_QUESTIONS.md` (Q1–Q35). Главные незакрытые:
Q23, Q25, Q26 (особенности модели Steele-MacInnis у критической точки CO₂ и границы клатрата выше 1 кбар);
Q24 (константы клатрата не сверены с первоисточниками); Q28 (объёмные корреляции неточны выше 150–200 °C —
расчёт по Th общ. выше 200 °C помечается как ориентировочный); Q32 (полной независимой валидации уравнения
Duan et al., 1995, нет); Q33 (окна интерпретации Te не калиброваны); Q34 (коэффициенты Sterner 1988 и
Steele-MacInnis 2011 взяты из постановки задачи, со сканами не сверены); Q35.

## Известные проблемы и оговорки

* Программа ни разу не запускалась на OSNova Onyx 2.7: вся разработка и тесты — в контейнере (Linux, Python
  3.13, Qt без экрана). Целевая конфигурация — Python 3.11 в окружении `fluidcalc`.
* `docs/TEST_REPORT.txt` и `validation/VALIDATION_REPORT.md` в репозитории получены в контейнере; на рабочей
  машине их нужно перезаписать запуском `./run_tests.sh`.
* Успешная интерпретация хранится в базе со статусом `ok` и входит в счётчик «рассчитано» в сводке расчёта;
  в таблице результатов и в экспорте она показана как «интерпретация (не расчёт)».
* Числа строгой модели H₂O–CO₂–NaCl отличаются от Excel автора: солёность до 0,3 % относительных, плотность до
  0,05 % (сошедшееся решение), изохора до 0,7 % (правильный перевод °C → K), бессолевые включения выше 250 °C —
  заметно (оговорка Mao для чистой воды). Объяснение — `validation/VALIDATION_REPORT.md`, разделы 16–18.
* Имя ветки по умолчанию техническое (`claude/brave-cori-42hlvf`). Переименовать её в `main` можно в GitHub:
  Settings → Branches → значок карандаша у ветки по умолчанию; ссылки при этом сохраняются.

## Команды

Запуск (на OSNova, окружение `fluidcalc` в `~/miniforge3`):

```bash
cd ~/FluidCalc && ./fluidcalc.sh
```

Проверки (перезаписывают `docs/TEST_REPORT.txt` и отчёт валидации):

```bash
cd ~/FluidCalc && ./run_tests.sh
```

Те же проверки в среде разработки без conda (нужны CoolProp, PySide6, matplotlib, openpyxl и системные
библиотеки Qt: libegl1, libgl1, libxkbcommon0, libfontconfig1, libdbus-1-3):

```bash
FLUIDCALC_PYTHON=$(which python3) ./run_tests.sh
```

### Обновление программы с сохранением базы

База данных лежит отдельно от программы: `~/.local/share/fluidcalc/fluidcalc.sqlite` (журналы — рядом, в
`logs/`). Обновление каталога программы её не затрагивает.

1. Закрыть FluidCalc и сделать копию базы:

```bash
cp ~/.local/share/fluidcalc/fluidcalc.sqlite ~/fluidcalc-копия-$(date +%F).sqlite
```

2. Обновить каталог программы. Если он получен через git:

```bash
cd ~/FluidCalc && git pull origin claude/brave-cori-42hlvf
```

   Если каталог скопирован архивом — распаковать новую версию поверх старой (или в новый каталог и заново
   выполнить `./install_desktop.sh`).

3. Запустить проверки, затем программу:

```bash
cd ~/FluidCalc && ./run_tests.sh
```

При первом открытии старой базы программа сама переводит её на схему v3 и кладёт рядом резервную копию
`fluidcalc.bak-vN-дата.sqlite`. Номера наблюдений и прежние расчёты сохраняются. Базу, открытую версией 0.5.0,
более старая версия программы не откроет («база создана более новой версией»): для возврата используйте копию.
